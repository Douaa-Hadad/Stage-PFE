## 1. Project Overview

This system implements an **intelligent microgrid energy management platform** for a hospital in Casablanca. It combines:

- **AI forecasting** — an LSTM-based neural network predicts real-time energy surplus/deficit, enabling proactive load management.
- **Blockchain P2P trading** — three Ethereum smart contracts (deployed on a local Hardhat network) handle tokenized energy units, enforce priority-based power allocation, and maintain an immutable audit ledger of every grid event and trade.
- **Real-time dashboard** — a Streamlit web application visualises live grid status, energy flows, weather conditions, battery state, and the full blockchain audit log.

### Hospital Priority Levels

The system enforces a strict 5-tier priority hierarchy during grid stress events:

| Level | Label | Examples |
|-------|-------|----------|
| P1 | **Critical** | ICU, operating theatres, life-support equipment |
| P2 | **High** | Emergency rooms, labs, pharmacies |
| P3 | **Medium** | General wards, radiology, administrative systems |
| P4 | **Low** | Cafeteria, guest Wi-Fi, non-essential lighting |
| P5 | **Deferrable** | EV chargers, laundry, scheduled maintenance loads |

### Energy Sources

| Source | Technology | Notes |
|--------|-----------|-------|
| Solar PV | Photovoltaic panels | Generation driven by Casablanca irradiance data |
| Wind | Turbines | Generation driven by local wind speed data |
| Battery | Lithium-ion storage | Charge/discharge managed by the AI controller |
| Grid | Utility tie-line | Fallback import/export with the public grid |

## 4. Generate the Dataset

Run each script in order, **from the `hospital_microgrid/` root directory**:

```bash
python scripts/generate_weather.py
python scripts/generate_supply.py
python scripts/generate_demand.py
python scripts/generate_batteries.py
python scripts/build_master.py
```

Or use the all-in-one setup script (recommended for first-time setup):

```bash
python setup.py
```

`setup.py` runs all 6 pipeline steps automatically, prints clear progress for each step, and stops immediately with a descriptive error message if any step fails.

### What each step produces

| Step | Script | Output |
|------|--------|--------|
| 1 | `generate_weather.py` | `data/weather/*.csv` |
| 2 | `generate_supply.py` | `data/supply/*.csv` |
| 3 | `generate_demand.py` | `data/demand/*.csv` |
| 4 | `generate_batteries.py` | `data/batteries/*.csv` |

## 5. Train the AI Model

```bash
python scripts/run_training.py
```

This trains the neural network (LSTM + dense layers) on `data/master_dataset.csv`.

**⏱ This step may take several minutes** depending on your hardware. GPU acceleration (CUDA) is used automatically if available via TensorFlow.

### What gets saved

After training completes, the following files are written to `models/trained/`:

| File | Contents |
|------|----------|
| `best_model.keras` | Model checkpoint with the lowest validation loss |
| `final_model.keras` | Model state at the final epoch |
| `history.json` | Training/validation loss and metrics per epoch |
| `training_log.csv` | Epoch-by-epoch tabular log |

> **Tip:** If model files already exist (i.e., you have trained before), you can skip straight to [launching the system](#6-launch-the-full-system).

## 6. Launch the Full System

The system requires **three services running simultaneously**:
1. Hardhat local blockchain node
2. Smart contract deployment
3. Streamlit dashboard

### Option A — One click (Windows only)

Double-click **`launch.bat`** in the `hospital_microgrid/` folder.

It automatically:
- Opens the Hardhat node in a new terminal window
- Deploys all three smart contracts
- Opens the Streamlit dashboard in another window
- Launches the dashboard in your browser at `http://localhost:8501`

### Option B — Manual (cross-platform, 3 terminals)

**Terminal 1** — Start the local blockchain node:
```bash
npx hardhat node
```
> Keep this terminal open. It logs every transaction in real time.

**Terminal 2** — Deploy the smart contracts (after the node is ready):
```bash
npx hardhat run scripts/deploy.js --network localhost
```
> This writes the deployed contract addresses to `deployments/`.

**Terminal 3** — Start the dashboard:
```bash
python -m streamlit run dashboard/app.py
```
> Opens at `http://localhost:8501`

### Option C — Skip training (model already trained)

If `models/trained/best_model.keras` already exists, skip Steps 1–6 of setup and go directly to Option A or B above.

## 7. Using the Dashboard

Open `http://localhost:8501` in your browser after launching.

### Pages

| Page | Description |
|------|-------------|
| **Grid Overview** | Real-time energy balance — generation vs. consumption, grid import/export, battery SoC gauge, AI forecast for the next interval. |
| **Energy Sources** | Live charts for solar PV output, wind turbine output, and weather conditions (irradiance, wind speed, temperature) pulled from the Open-Meteo API. |
| **Priority Management** | Per-priority load breakdown (P1–P5). Includes the **Simulate Grid Failure** button which triggers the `PriorityGuard` contract to cut non-critical loads and logs the event on-chain. |
| **Blockchain Audit Log** | Full immutable ledger of grid events (failures, restores) and P2P energy trades, read directly from the deployed smart contracts. |

### Theme Toggle

Click the **🌙 / ☀️ pill** in the top-right corner to switch between dark and light mode. The preference is saved in your browser and requires no page reload.

## 9. Project Context

This project is the **Bachelor Final Year Project (PFE)** for the degree in Computer Science / Software Engineering at [University/School name], Casablanca, Morocco (2025–2026).

### Problem Statement
Hospitals are critical infrastructure that cannot afford power interruptions. In Morocco and across the developing world, unreliable grid supply and rising energy costs make self-sufficient microgrids a strategic priority. However, managing a microgrid — balancing renewable generation, storage, and variable hospital loads — is too complex for manual control.

### Our Solution
We built an autonomous microgrid management system that uses:
- **AI (LSTM neural network)** to predict short-term energy surplus or deficit, enabling proactive decisions before shortages occur.
- **Blockchain smart contracts** to enforce priority-based power allocation with cryptographic guarantees, and to enable transparent peer-to-peer energy trading between hospital zones.
- **Real-time dashboard** to give operators full visibility and manual override capability.

### Key Research Contributions
1. A synthetic but realistic dataset of hospital energy demand, solar/wind supply, and battery dynamics for Casablanca's climate.
2. An LSTM model trained on 5-minute interval data with multi-feature inputs (weather, load history, SoC).
3. A smart contract architecture (EnergyToken + PriorityGuard + EnergyMarket) that enforces medical-grade load shedding rules on-chain.
4. A full-stack prototype demonstrating AI + blockchain integration in a hospital energy context.
